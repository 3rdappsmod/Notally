# Notally 누적 변경 재검토

2026년 10월 4일, `cf1b331..058095a`의 병합을 제외한 62개 커밋 이력과 현재 누적 소스를 검토했다. SDK·빌드 이전, CI, 저장과 복원, 편집기, 정렬, 위젯, 오디오, 파일 내보내기 변경을 중심으로 확인했다. 개별 과거 커밋을 각각 빌드한 것은 아니며 최종 소스에 회귀 테스트와 빌드 검증을 적용했다.

전체적인 변경 방향은 적절하다. 아래 세 가지 문제는 수정 전 테스트 실패로 재현했고 수정했다. 자동 테스트는 실제 Gboard와 런처의 동작까지 보증하지 않는다.

검토 시작 시 현재 브랜치는 `feat/editor-navigation-and-note-tools`이고 HEAD는 PR #35 병합 커밋 `058095a`였다. 로컬 `master`와 `origin/master`는 `22d59ff`에 머물러 있었다. 따라서 최신 병합 내용을 포함한 HEAD에서 `fix/editor-review-regressions`를 만들었다. 원격의 현재 브랜치 보호 설정이나 PR 상태는 이번에 변경하거나 재검증하지 않았다.

## 수정 내용

### 체크리스트 이동 순서

`a, b, c, d`에서 첫 항목을 네 번째 위치로 이동하면 데이터는 `d, b, c, a`가 되지만 화면에는 한 항목을 이동했다고 알리고 있었다. 빠르게 여러 칸을 이동할 때 표시와 실제 데이터가 달라질 수 있다.

두 끝 항목을 교환하던 코드를 항목 제거 후 목적지에 삽입하는 방식으로 바꿨다. 이제 `b, c, d, a`가 되며 역방향 이동과 Undo/Redo도 같은 순서를 유지한다. 같은 위치로 이동하는 요청은 무시한다.

이는 중간 항목의 위치가 함께 이동하는 [RecyclerView의 notifyItemMoved 계약](https://developer.android.com/reference/androidx/recyclerview/widget/RecyclerView.Adapter#notifyItemMoved(int,int))에 맞춘 수정이다.

### 제목과 체크리스트의 공백 복원

입력할 때마다 `trim()`을 적용해 모델에 넣으면 `hello`, 공백, `world` 순서로 입력한 뒤 Undo했을 때 `hello `가 아닌 `hello`로 돌아간다. 공백만 입력한 변경도 이력에서 사라졌다.

편집 모델에는 입력한 문자열을 그대로 보관하고 DB 저장용 사본에서만 기존처럼 앞뒤 공백을 정리한다. 공백만 있는 새 메모를 종료하면 삭제하는 동작도 유지한다. 제목과 실제 체크리스트 입력칸을 통한 Undo/Redo 및 DB 저장 정규화를 테스트했다.

### 위젯 변경 직후의 오래된 캐시

DB의 체크 상태가 갱신돼도 목록 캐시가 갱신되기 전에 편집기를 열면 이전 체크 상태를 불러올 수 있었다. 그대로 저장하면 새 체크 상태를 덮어쓸 위험도 있었다. Room의 LiveData 조회는 백그라운드에서 비동기로 실행되므로 캐시 갱신 시점과 편집기 진입 시점은 같다고 가정할 수 없다. [Android LiveData 문서](https://developer.android.com/topic/libraries/architecture/livedata)

편집기를 처음 열 때 IO 디스패처에서 DB의 현재 행을 읽도록 변경했다. 체크리스트의 가변 항목도 사본으로 가져온다. 사용처가 없어진 전체 노트 캐시와 `observeForever` 등록도 제거했다. 수정 전 오래된 캐시를 의도적으로 남긴 테스트가 API 28과 37에서 실패했고 수정 후 통과했다.

## 유지한 설계

- Dependabot patch/minor 자동 병합, major 및 사람이 작성한 PR의 수동 병합은 합의된 정책이다. 자동 병합 자체를 결함으로 판단하지 않았다. CI 파일에는 테스트·lint·debug 및 release 빌드가 모두 포함돼 있다.
- target/compile SDK 37, minSdk 26, 내장 Kotlin 및 새 DSL 설정을 유지했다. 단순히 경고를 숨기는 설정은 추가하지 않았다.
- Room 5→6 마이그레이션은 기존 생성일을 수정일의 초기값으로 사용한다. 이전 백업에서 수정일이 없을 때의 처리, 생성일 유지, 핀 우선 정렬을 확인했다.
- 안정적인 노트 ID 예약, 빈 기존 메모 저장, 회전 시 편집 복원, 결과 콜백의 초기화 대기 코드를 확인했다.
- 위젯의 API별 컬렉션 처리, 큰 컬렉션의 기존 서비스 경로, 오래된 체크 요청 방어를 확인했다.
- 재생 포그라운드 서비스와 알림 정리, Glide 5 파일 로딩, PDF 오류 및 자원 정리 변경을 기존 회귀 테스트와 함께 확인했다.
- lint baseline은 기존 번역 누락만 대상으로 유지했다. 이번 수정으로 baseline을 넓히지 않았다.

## 검증 범위와 남은 제한

다음 명령으로 검증했다. JDK 25와 설치된 Android SDK를 사용했다.

```sh
./gradlew testDebugUnitTest lintDebug assembleDebug assembleRelease --offline --console=plain --continue
```

- 단위·Robolectric 테스트 83개 통과, 실패·오류·건너뜀 0개.
- `lintDebug` 통과. 기존 경고 56개, 기존 번역 오류 78개는 baseline으로 제외됐다.
- debug 및 R8 최적화 release APK 빌드 성공. release 서명과 설치는 사용자의 기존 절차를 따른다.
- `git diff --check` 통과.

별도 작업 사본에서 검증한 뒤 같은 커밋을 원래 저장소의 새 브랜치로 가져왔다.

Undo 이력은 편집 화면의 ViewModel 수명 동안 유지되며 프로세스 종료 후 복원되는 영구 이력은 아니다. 여러 편집 화면이나 위젯에서 동일 메모를 동시에 편집하는 충돌 병합 기능도 이번 수정에 포함되지 않는다. 캐시 수정은 편집기를 새로 열 때의 최신 상태 조회를 보장하는 변경이다.

기존 deprecated 경고와 lint 경고가 남아 있으므로 앞으로의 Gradle·AGP major 업데이트는 계속 별도 검증해야 한다. 실제 기기의 Gboard와 런처는 여기서 실행하지 않았다.

실기기 확인은 새 APK에서 체크리스트를 여러 칸 이동하고, 제목 또는 항목에 단어·공백·단어를 입력한 뒤 Undo/Redo하는 짧은 확인이면 충분하다. 위젯을 사용한다면 체크 변경 직후 해당 노트를 열어 상태가 유지되는지만 추가 확인한다.
