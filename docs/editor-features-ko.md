# 편집기 커서 표시와 메모 정렬 및 실행 취소

2026년 10월 4일 요청에 따라 세로 화면에서 키보드에 커서가 가려지는 문제를 수정하고,
빠른 이동과 Undo/Redo, 메모 정렬 기능을 추가했다. 기준 소스는 `bcc3a5b`이다.

## 사용 방법

- 편집 화면 아래 도구줄: 맨 위 이동, 실행 취소, 다시 실행, 맨 아래 이동.
  키보드가 열린 상태에서도 도구줄이 키보드 위에 배치된다.
- 설정 → 메모 정렬 기준: 작성일, 수정일, 제목. 정렬 방향에서 오름차순·내림차순을 선택한다.
  고정한 메모는 항상 앞에 두며, 검색·라벨·보관함·휴지통과 위젯 노트 선택에도 정렬을 적용한다.
- 색상·고정·라벨은 원래 있던 기능을 유지한다. 메모 목록에서 메모를 길게 눌러 관리할 수 있다.
- 링크는 본문에서 전화번호·이메일·웹 주소를 선택한 뒤 선택 메뉴의 링크 기능으로 지정한다.
  이번에는 `example.com/path`처럼 경로가 있는 주소도 스킴이 없으면 HTTPS로 열도록 보강했다.

## 커서 표시와 편집 기록

키보드 높이만큼 여백을 확보한 다음, 크기가 바뀐 스크롤 영역의 레이아웃이 끝난 뒤
현재 편집 중인 커서 한 줄이 보이도록 요청한다. 메모 입력칸 전체를 대상으로 삼지 않는다.
커서 이동·입력에도 같은 처리를 적용한다. 맨 위·아래 버튼은 커서 선택 위치를 바꾸지 않고
내용을 스크롤한다.

Undo/Redo는 제목, 본문과 서식, 체크리스트의 내용·추가·삭제·체크·순서 변경을 대상으로 한다.
사진·녹음 파일 삭제나 메모 자체의 삭제를 되돌리는 기능은 아니다.
ViewModel에 기록을 보관하므로 회전에도 유지되지만, 편집 화면을 닫거나 프로세스가 종료되면
편집 기록은 보존하지 않는다. 기록은 최대 100건이며 텍스트 저장량에 따라 오래된 기록부터
줄인다. 가장 최근 작업 하나는 유지한다.

전체 Undo 후 새 입력을 했을 때 오래된 Redo가 남는 원본 구현 문제를 수정했다.
행을 다시 표시하는 작업은 편집으로 기록하지 않으며, 회전 시 이전 입력 감시기를 해제한다.
한글 등 조합 입력 중 실행 취소를 누르면 조합 상태를 정리하고 키보드 입력 상태를 갱신한다.

## 원본 커밋과 이식 방식

NotallyX의 원본 커밋에 `git cherry-pick -x --no-commit`을 실행한 뒤 충돌을 해결했다.
원본에는 다른 패키지명, 계층형 체크리스트와 별도 어댑터 구조가 있어 현재 포크에 필요한
부분을 재구성했다. 따라서 원본 커밋을 변경 없이 적용한 것은 아니다.

- [59a0a8cc 실행 취소와 다시 실행](https://github.com/Crustack/NotallyX/commit/59a0a8cca18c3e9077834fb5884157bd76ebe9b1)
- [5b9f9680 작성일 수정일 제목 정렬](https://github.com/Crustack/NotallyX/commit/5b9f9680fc864c2fbfec27e5c7844dd16b2b9c18)
- [8ba10783 맨 위와 아래 이동](https://github.com/Crustack/NotallyX/commit/8ba10783594d1778ee87c6e01f0449097ac9631c)의 아이콘과 기능 구성을 참고했다.

Undo/Redo와 정렬 원본 작성자는 PhilKes, 이동 기능 원본 작성자는 Crustack이다.
추가 UI 번역은 NotallyX `1e745f1eca5168976901285db3b9a8571c494b4f`의 리소스를 활용하고,
현재 포크의 한국어 등 누락된 언어 리소스를 보완했다. 원본과 이 포크의 GPL 3.0 라이선스를 유지한다.

## 데이터 보존과 수정일

Room DB를 버전 5에서 6으로 이전하고 `modifiedTimestamp`를 추가한다.
기존 메모의 수정일 초기값은 실제 작성일 값을 복사한다. SQL 기본값에 문자열 `timestamp`를
넣는 원본 이전 코드는 사용하지 않는다. 단순 열기·닫기로 수정일을 갱신하지 않으며,
내용이나 메타데이터 변경, 위젯에서의 체크 등에는 수정일을 갱신한다.

새 백업은 수정일을 포함하고, 기존 백업에 해당 열이 없으면 작성일을 사용한다.
기존 작성일·첨부·라벨을 지우거나 데이터베이스를 초기화하는 이전 방식은 사용하지 않았다.

## 검증 결과

JDK 25에서 다음 명령이 통과했다.

```sh
./gradlew testDebugUnitTest lintDebug assembleDebug assembleRelease --offline --console=plain --continue
```

- 테스트 76개 통과, 실패·건너뜀 0개.
- DB 5→6 이전, 구형·신형 백업 수정일 복원, 변경 없는 저장의 수정일 유지 검증.
- 정렬과 고정 우선순위, 전체 Undo 후 Redo 폐기, 실제 편집기의 Undo/Redo와 서식 복원 검증.
- 회전 후 편집 기록 유지, 조합 표시 해제, 키보드를 연 뒤 커서가 화면 안에 보이는지 검증.
- debug 및 최적화된 unsigned release APK 생성 성공.
- lint의 기존 경고 56개와 번역 누락 baseline 78건 유지. 새 오류를 baseline에 추가하지 않았다.

## 최소 실기 확인

자동 테스트는 실제 Gboard와 기기별 창 애니메이션을 완전히 재현하지 못하므로 새 빌드에서 확인한다.

1. 세로 화면에서 긴 메모 아래쪽을 눌러 키보드를 열고 한글 두 줄을 입력한다.
   회전하지 않아도 커서가 키보드와 도구줄 위에 보이는지 확인한다.
2. 맨 위·아래 이동과 Undo/Redo를 누르고, 회전 후에도 편집 내용과 기록이 유지되는지 확인한다.
3. 설정에서 제목순·수정일순을 선택하고, 기존 메모 한 개를 수정한 뒤 목록 순서를 확인한다.

실기 검증은 아직 완료하지 않았다. Git push와 GitHub PR 작업은 사용자가 수행한다.
