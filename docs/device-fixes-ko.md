# 실기기 검사 결과와 후속 수정

## 사용자가 확인한 환경과 결과

- 기기: Mi 11 Lite 5G
- OS: Android 17, AOSP 기반 PixelOS 커스텀 ROM
- APK: 사용자가 직접 빌드한 release (SDK 37 / Glide 5 병합 후)
- 일반 메모의 회전·키보드·저장 및 이미지 표시·스크롤·확대·삭제: 통과
- 녹음의 홈 이동·화면 잠금 중 재생: 통과
- 재생 알림: 처음에는 앱 알림이 비활성화되어 보이지 않았음.
  사용자가 권한을 켠 후 알림 표시·일시정지·앱에서 이어 재생까지 통과.

재생 알림은 추가 결함으로 취급하지 않는다. 사용자 원본 검사 파일은
덮어쓰지 않았으며, 위 내용에는 대화에서 추가로 확인한 결과도 포함했다.

## 수정한 두 문제

1. **끝까지 재생한 뒤 재생 막대가 끝에 머무는 문제**
   기존 화면은 한 번 읽은 재생 위치에 경과 시간을 더했다. 기기의 플레이어가
   재시작 위치를 비동기로 갱신하면 끝 위치를 계속 기준으로 삼을 수 있었다.
   이제 화면이 표시되고 재생 중일 때 실제 플레이어 위치를 100ms마다 읽는다.
   화면 종료·서비스 연결 해제 시 위치 조회와 화면 갱신을 해제한다.
2. **체크리스트 회전 후 키보드와 커서가 사라지는 문제**
   편집하던 행 번호와 커서 선택 범위를 저장하고, 모델 로딩 및 RecyclerView의
   행 배치가 끝난 뒤 해당 입력칸에 포커스와 커서를 복원한다.
   키보드는 회전 전 표시되어 있었을 때만 다시 요청한다.

## 수정 후 사용자가 다시 확인할 것 — 두 가지뿐

- [x] 짧은 녹음을 끝까지 재생한 뒤 다시 재생한다. 진행 막대가 처음으로
  돌아와 소리와 함께 움직이는지 확인한다. 일시정지·재개도 한 번 확인한다.
- [ ] 체크리스트 두 번째 항목의 문장 중간을 편집하면서 가로·세로 회전한다.
  같은 항목에 커서와 키보드가 복원되는지 확인한다. 키보드를 닫고 한 번 더
  회전했을 때는 키보드가 다시 열리지 않아야 한다.

이미 통과한 전체 검사를 반복할 필요는 없다. 재생 막대는 사용자가 수정 APK에서 정상 동작을 확인했다. 체크리스트는
아래 기기별 키보드 표시 모드 차이에 대한 후속 확인이 남아 있다.

## 자동 검증

다음 명령으로 빌드 산출물을 정리한 상태에서 전체 검증을 통과했다.

```sh
./gradlew clean testDebugUnitTest lintDebug assembleDebug assembleRelease --no-parallel --console=plain --continue
```

- 테스트 49개: 실패·건너뜀 0개.
- 신규 재생 화면 회귀 테스트: API 26·37에서 재시작 시 위치 재동기화와 일시정지 확인.
- 신규 체크리스트 회귀 테스트: API 28·37에서 Activity 재생성 후 두 번째 행과 선택 범위·내용 복원 확인.
- debug 및 축소 적용 unsigned release 빌드 통과.
- lint: 새 오류 0개, 경고 60개. 기존 번역 오류 78개의 baseline은 변경하지 않음.
- actionlint 및 git diff --check 통과.

키보드의 실제 표시 여부와 기기 MediaPlayer 동작은 위 자동 테스트만으로
확정할 수 없으므로, 아래 체크리스트 가로 입력 재확인은 아직 남아 있다.


## 가로 화면의 전체화면 키보드 대응

사용자 추가 확인: 재생 막대는 정상. Android 17 PixelOS에서 Mi 11 Lite 5G는
플로팅 키보드가 체크리스트 내용을 가리고, OnePlus 13T는 전체화면 입력 UI가
체크리스트를 가린다. 사용자는 두 기기 모두 Gboard를 사용한다고 확인했다.
두 화면 모두 입력하기 불편하다는 보고이며, Mi 11의 표시도 정상 판정하지 않는다. 스크린샷과 사용자 설명상 이전의 커서 소실 문제와는
별개로, 키보드 표시 모드 차이에 해당한다.

체크리스트 항목과 제목에 `IME_FLAG_NO_FULLSCREEN` 요청을 추가했다.
기존 `actionNext`, 커서 복원, 키보드가 닫혀 있던 상태의 복원은 유지한다.
키보드를 플로팅 모드로 강제하는 것은 아니며, 키보드가 요청을 따르면
앱 화면을 남기는 일반 입력 모드를 사용한다.

수정 후 OnePlus 13T에서 **체크리스트 항목 입력 → 가로 회전 → 항목과 커서가
보이는지 확인 → 다음 항목 이동**만 다시 확인하면 된다. 제목 입력도 같은
방식으로 확인한다. 특정 키보드는 요청을 무시할 수 있으므로 기기 동작까지
자동 테스트로 확정하지는 않는다.

근거: [Android EditorInfo 문서](https://developer.android.com/reference/android/view/inputmethod/EditorInfo#IME_FLAG_NO_FULLSCREEN).


### Gboard 플로팅 모드는 별도 설정

`flagNoFullscreen`은 전체화면 입력 UI를 제한하도록 요청하는 옵션으로,
플로팅 모드를 하단 고정 모드로 강제하지 않는다. Mi 11에서는 가로 화면에서
Gboard 메뉴의 플로팅 모드를 끄거나, 키보드 아래 이동 핸들을 화면 하단으로
끌어 하단에 고정한 뒤 확인한다. 같은 Android 버전이라도 Gboard 설정이나
버전에 따라 표시 모드가 다를 수 있다. 앱에서 시스템 키보드의 위치를
임의로 바꾸는 비공개 설정은 사용하지 않는다.
