# 2026-09-26 코드 검토 후속 수정

검토 기준: `9d9a248` (PR #30 병합). 기존 작업 기록에 있는 상태표시줄,
서랍 메뉴 및 내비게이션 바의 실기 검증 결과는 유지한다.

## 수정 내용

- 편집기와 메인 검색 화면의 하단 여백에 `max(systemBars/displayCutout, ime)`를
  적용한다. 키보드가 닫히면 시스템 바 여백으로 돌아오며, 여백을 중복 누적하지 않는다.
  메인 화면에도 `adjustResize`를 명시해 키보드 inset 전달을 지원한다.
- 노트 편집기의 이미지 추가/삭제, 라벨 선택, 녹음 추가/삭제 및 알람 권한 결과는
  비동기 노트 초기화가 끝난 뒤 처리한다. 복원 도중 도착한 결과를 이전 DB 값이
  덮어쓰거나 아직 준비되지 않은 노트에 적용하는 경쟁을 방지한다.
- lint baseline을 `22d59ff`의 번역 누락 78건으로 복원한다. 번역 외 경고를
  일괄 등록하지 않으며, 경고가 줄어든 것처럼 보이게 하는 갱신을 피한다.

## 자동 검증

원본 HEAD의 임시 복사본에 수정 사항을 적용하여 JDK 25로 실행:

```sh
./gradlew testDebugUnitTest lintDebug assembleDebug assembleRelease --offline --console=plain
```

- 테스트 57개 통과, 실패 및 건너뜀 0개.
- `lintDebug`: 제외되지 않은 오류 0개, 경고 60개. 기존 번역 오류 78건만 baseline으로 제외.
- debug 및 최적화된 unsigned release APK 빌드 통과.
- 새 키보드 테스트: Android 17에서 편집기/검색 화면의 키보드 표시·반복 inset 전달·숨김 확인.
- 새 결과 처리 테스트: Android 9 및 17에서 노트 로딩 전에 라벨 결과를 전달하고,
  로딩 이후 해당 결과와 기존 제목/노트 ID가 유지되며 DB에 저장되는지 확인.

키보드 테스트는 합성 inset을 사용한다. 실제 Gboard의 배치·스크롤·회전 동작을
완전히 대신하지 않는다. Android 9에서는 이 방식으로 타입별 IME inset을 전달할 수
없었고, Android 11까지 함께 실행했을 때 Robolectric의 네이티브 폰트 로더 충돌이
발생해 키보드 테스트는 Android 17로 한정했다. 결과 복원 테스트의 Android 9/17
검증 범위는 유지했다.

## 남은 최소 실기 확인

새 커밋으로 빌드한 앱에서 Gboard를 하단 고정한 상태로 긴 체크리스트의 아래쪽 항목을
편집하며 세로→가로→세로로 회전한다. 입력 중인 행이 키보드 위로 스크롤 가능한지,
키보드를 닫았을 때 불필요한 하단 공백이 남지 않는지만 확인한다.
Gboard 플로팅 모드의 위치는 앱이 제어하지 않는다. 이번 변경의 실기 검증은 아직 하지 않았다.
